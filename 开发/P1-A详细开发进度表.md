# P1-A详细开发进度表

## 一、使用方式

这份文档是后续开发的主执行清单。

每次开启新对话或继续开发前，先确认：

1. 当前Git分支是否为`mvp`。
2. 当前版本基线是否为`v0.0.1`或后续新标签。
3. `开发/项目开发计划.md`中的当前阶段。
4. 本文档中第一个未完成阶段。
5. 是否存在未提交代码。

开发顺序原则：

- 按阶段推进，不跳阶段。
- 每个阶段完成后更新本文档状态。
- 每个阶段完成后至少做一次基础验证。
- 每个阶段完成后提交Git。
- 业务规则不清楚时向用户提问。
- 技术实现细节由开发者自行决策。
