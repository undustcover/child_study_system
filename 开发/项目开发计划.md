# 项目开发计划

## 一、当前项目定位

项目当前处于：

> P1-A电脑端开发准备阶段。

当前版本：

```text
v0.0.2
```

当前目标不是开发完整学生学习系统，而是先完成：

> 面向一个学生的学习计划、提醒、计时、休息、语音执行和统计闭环。

当前硬件已选定：

```text
ESP32-S3-BOX-3
```

当前开发重点：

```text
电脑端后端 + 家长Web管理端 + 设备通信协议 + 虚拟设备模拟器
```

### 阶段2：核心数据模型与日历计划管理

状态：未开始

目标：

- 实现学生模型。
- 实现日历计划。
- 实现计划任务项。
- 实现单日例外。
- 实现节假日和寒暑假日期标签。

### 阶段3：状态机与学习会话

状态：未开始

目标：

- 实现统一命令处理器。
- 实现任务状态机。
- 实现学习会话。
- 实现计时段。

- 计划结束不自动完成，只进入待确认结束。

- 实现休息结束提醒。

- 实现基础播报模板。

完成标准：

- 到点后后端能主动生成提醒事件。
- 提醒内容能进入统一播报通道。
- 提醒记录能保存。

### 阶段5：设备WebSocket协议

状态：未开始

目标：

- 实现设备WebSocket连接。
- 实现设备注册。
- 实现设备在线状态。
- 实现后端下发`speak`。

- 实现设备上报`playback_finished`。

完成标准：

- 没有真实BOX-3时，协议仍能被虚拟设备调用。
- 后端业务不区分真实设备和虚拟设备。

### 阶段6：虚拟设备模拟器

状态：已完成

目标：

- 编写Python CLI虚拟设备。
- 连接后端WebSocket。
- 接收播报和屏幕状态。
- 输入命令模拟学生语音。

完成标准：

- 输入`start`能触发`START_STUDY`。
- 输入`complete`能触发`COMPLETE_STUDY`。
- 虚拟设备接收后端提醒并打印。
- 虚拟设备与真实设备使用同一协议。

### 阶段7：家长Web管理端

状态：未开始

目标：

- 今日计划页面。
- 当前任务状态页面。
- 日历计划页面。
- 今日统计页面。
- 家长纠错入口。
- 设备在线状态展示。

完成标准：

- 家长可以完成计划维护。
- 家长可以查看学生执行状态。
- 家长可以修正错误记录。
- 学生主流程不依赖Web点击。

### 阶段8：P1-A端到端验收

状态：未开始

目标：

完整跑通：

```text
创建日历计划
-> 生成今日计划
-> 到点提醒
-> 虚拟设备播报
-> 虚拟设备输入start
-> 后端开始计时
-> 到结束时间请求确认
-> 虚拟设备输入complete
-> 生成今日统计
```

完成标准：

- 能不接真实BOX-3完整验证P1-A闭环。
- 后端已经按真实BOX-3接入方式设计。
- 后续真实固件接入不需要重构核心业务。

## 五、开发路线判断

当前不建议：

- 先写真实设备固件。
- 只做Web页面，不做设备协议。
- 只留接口，暂不实现虚拟设备。
- 把Web点击作为学生执行主流程。
- 现在开发自然语言助手。
- 现在开发AI学习诊断。

当前建议：

- 后端按设备优先设计。
- Web端按家长控制台设计。
- 设备协议和虚拟设备尽早实现。
- 所有命令走统一命令处理器。
- 真实BOX-3以后只替换设备实现层。

## 六、P1-A验收口径

P1-A成功的标准不是页面完整，也不是语音AI强大。

P1-A成功的标准是：

> 在没有真实ESP32-S3-BOX-3的情况下，系统已经可以用虚拟设备完整模拟学生语音执行学习计划，并由电脑端准确完成提醒、状态流转、计时和统计。

真实BOX-3接入后，目标是：

> 设备只需要遵守协议，后端核心业务不重写。
